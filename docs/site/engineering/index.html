02 · Runtime architecture

A server-backed PWA with a local working set.

Next.js is both the application shell and backend-for-frontend. PostgreSQL functions own high-integrity mutations; Inngest handles work that must survive the request; IndexedDB keeps the kitchen usable through a weak connection.

03 · Photo-to-inventory flow

AI proposes. People commit.

Raw photo bytes have a short, controlled life. The user-visible batch and the storage objects are tracked separately so processing, review, and purging can be retried safely.

01

Prepare on device

The client accepts 1–3 photos, re-encodes to JPEG, limits the longest edge to 1600 px, strips EXIF, and enforces a 5 MB cap before upload.

02

Create descriptors

POST /api/v1/analyses validates file metadata and creates an analysis plus bounded image assets. Production returns signed upload grants for the private raw-images bucket.

03

Commit the upload set

The completion route verifies object ownership, count, type, and byte size, moves the analysis to queued, then emits foodtopia/analysis.requested. A recovery cron redispatches stale committed rows.

04

Analyze durably

Inngest resolves the household’s encrypted BYO credential, downloads the exact assets, requests structured output from OpenAI or OpenRouter, normalizes concepts, and stores review candidates.

05

Review and apply atomically

The model output is inert. The user accepts, edits, or rejects each candidate; apply_analysis_candidates creates lots, commands, and immutable events in one PostgreSQL transaction.

06

Delete raw bytes

Apply and cancel attempt immediate removal. A scheduled sweeper claims leftovers, removes objects, and records tombstones; no uploaded photo may remain beyond 24 hours.

04 · Offline-first inventory

Optimistic locally. Ordered globally.

The service worker keeps only the shell and static assets. Household data lives in a tenant-bound Dexie database and is reconciled through versioned commands when connectivity returns.

Offline write + synchronization

device → server → device
Sync runs on launch, focus, reconnect, visibility return, and every 15 seconds while foregrounded. Replay stops at the first conflict so later commands cannot overtake it.

05 · Recipe selection & cooking

Determinism before generation.

AI may parse a natural-language intent and add optional explanations, but readiness comes from project-owned TypeScript: normalized concepts, unit conversion, quantity certainty, accepted forms, and curated substitutions.

A

Load trusted context

Published recipes, approved household recipes, active lots, staples, dietary preferences, and exclusions are loaded under the current household session.

B

Build ingredient evidence

Every required ingredient becomes present_sufficient, present_quantity_unknown, insufficient, missing, or ambiguous. Name-only custom lots never become recipe evidence.

C

Rank explainably

Tier → missing count → substitution count → use-soon count → unknown quantity → prompt fit → duration → stable ID. Only recipes with at most two required gaps surface.

D

Generate only on zero match

One strict private draft may be generated when the catalog yields nothing. It is rate-limited, expires after 24 hours, and cannot be cooked until approval materializes a household recipe.

E

Cook against a snapshot

A cook session freezes recipe evidence and servings. The durable local context survives a restart; reconciliation confirms per-lot usage against expected versions and emits normal inventory commands.

07 · Security & privacy

Defense follows the data.

UI redirects improve experience; they are not the security boundary. Every protected API independently verifies Auth, account admission, and database-derived membership before RLS applies the same tenant boundary again.

Verified identity

supabase.auth.getUser() validates the request with Supabase Auth; claims alone are not trusted.

Admission wall

The caller’s own profile must be enabled. Pending and disabled accounts receive 403 from data APIs.

Derived tenancy

The server reads the sole membership through RLS. Protected functions do not accept a household ID from the client.

Database enforcement

RLS, scope triggers, immutable-row triggers, expected versions, and transactional RPCs protect every mutation path.

Short-lived raw data

Storage paths include the household and analysis; signed upload grants are bounded; retention workers verify deletion.

BYO AI credentials

Each household owner supplies an OpenAI or OpenRouter key. The browser can replace or clear it, but can never read it back.

  • AES-256-GCM ciphertext in the private schema
  • Rotating server keyring with compare-and-swap re-encryption
  • Provider and model allowlists
  • No deployment-level fallback key
  • Missing or unreadable credentials fail closed

08 · Delivery & operations

Designed for recoverable failure.

Production runs on Vercel with Supabase and Inngest as managed dependencies. Scheduled recovery is based on committed database state, so event delivery and cleanup can be safely repeated.

3×Analysis retries

Transient provider failures retry; model refusals are terminal and never replayed as success.

10 · Scope boundaries

Know what the system does not promise.

These constraints are part of the architecture, not missing polish. They keep the alpha’s evidence and safety claims narrow enough to defend.

Built and supported

  • One shared household per account
  • Photo-assisted inventory with review
  • Offline inventory commands and recipe browsing
  • Deterministic readiness and curated substitutions
  • Private household recipe drafts
  • Shopping list, favorites, and cook history

Explicitly out of scope

  • Allergen, nutrition, freshness, or edibility guarantees
  • Receipt OCR or automatic printed-date extraction
  • Meal calendars or nutrition optimization
  • Public AI-generated recipes
  • Push reminders, billing, or native apps
  • Multi-household switching
